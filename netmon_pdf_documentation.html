1. Ringkasan Eksekutif & Fitur Utama

NetMon adalah aplikasi pemantauan jaringan terintegrasi yang dirancang khusus untuk memonitor infrastruktur jaringan lokal (LAN) maupun WAN secara asinkron dengan visualisasi interaktif. Sistem ini menyediakan pemantauan status perangkat real-time, grafik throughput lalu lintas data per-router, pemetaan fisik interaktif denah lantai (floor plan), auto-discovery perangkat, serta sistem analisis akar penyebab downtime (diagnostik Forensik) berbasis AI/Heuristik.

Fitur Utama & Karakteristik Sistem

  • Dual-Interval Polling: Memisahkan polling keaktifan status perangkat (default 30s) dengan polling counter bandwidth router (default 10s) untuk performa database dan presisi throughput optimal.
  • Interactive Floor Plan Canvas: Denah lantai interaktif berbasis canvas GPU acceleration (riak radar visual) dengan fitur drag-and-drop koordinat perangkat.
  • Network Discovery (Subnet Auto-Scan): Pencarian host dalam subnet menggunakan ping ICMP dan probe OID SNMP secara dinamis.
  • AI False Warning Filter: Verifikasi asinkron alert offline menggunakan jeda retry, ping ganda, dan analisis Groq API (Llama 3.3 70B) untuk menyaring alarm palsu akibat jitter WSL/virtual switch.
  • BlackBox Forensics Engine: Analisis kegagalan jaringan secara mandiri berdasarkan sensor telemetri (Suhu, RAM leak, DDoS attack, atau mass downtime Upstream Fiber Cut).
  • Split Data Retention: Pemisahan retensi data grafik resolusi tinggi (7 hari) dan metrik bulanan laporan (60 hari) guna efisiensi disk.

3. Panduan Instalasi & Konfigurasi Layanan

Instalasi di lingkungan Linux disarankan menggunakan skrip installer otomatis demi keamanan hak akses pengguna sistem.

A. Instalasi Otomatis (Linux / WSL)

# 1. Clone source code
git clone https://github.com/bagusazizulamri/netmon.git
cd netmon

# 2. Jalankan skrip installer (memerlukan sudo)
sudo bash install.sh

Skrip `install.sh` akan mengotomatiskan pembentukan virtual environment python, instalasi dependencies, inisialisasi basis data `netmon.db`, pendaftaran systemd daemon `netmon.service`, dan konfigurasi port firewall UFW 5000.

B. Manajemen Layanan Daemon Linux

# Memulai daemon NetMon
sudo systemctl start netmon

# Menghentikan daemon NetMon
sudo systemctl stop netmon

# Restart daemon (misal setelah konfigurasi env)
sudo systemctl restart netmon

# Membaca log output daemon secara real-time
sudo journalctl -u netmon -f

C. Hapus Instalasi Secara Bersih (Uninstall)

Gunakan berkas uninstaller bawaan untuk menghapus seluruh komponen sistem:

sudo bash uninstall.sh

4. Konfigurasi Database & Skema Tabel

NetMon menggunakan SQLite sebagai mesin persistensi data. SQLite dipilih karena keandalannya yang tinggi, tanpa memerlukan konfigurasi service server tambahan, serta efisiensi mmap I/O yang sangat cepat.

Lokasi Database: Secara default, berkas database terletak di root projek dengan nama netmon.db. Path ini dapat diubah menggunakan environment variable DB_PATH.

Skema Tabel Utama

Tabel: devices

Nama Kolom Tipe Data Keterangan

5. Optimasi Performa & SQLite PRAGMA Tuning

Ketika volume data telemetri di tabel snmp_metrics melampaui ratusan ribu baris, kueri standard SQLite dapat memicu disk bottlenecks. NetMon menerapkan optimasi PRAGMA pada inisialisasi koneksi asinkron di file database.py:

A. Koneksi PRAGMA Tuning

  • journal_mode = WAL: Mengaktifkan mode Write-Ahead Logging yang mengizinkan proses pembacaan (read) dari API Flask dan penulisan (write) dari thread SNMP polling berjalan bersamaan tanpa saling mengunci (concurrency locks).
  • synchronous = NORMAL: Mengurangi pemanggilan flush disk secara terus-menerus. SQLite hanya melakukan flush pada checkpoint WAL tertentu, meningkatkan kecepatan transaksi penulisan metrik.
  • temp_store = MEMORY: Menyimpan data tabel temporer hasil filter query (e.g. sorting tanggal) di RAM server untuk menghemat operasi I/O disk fisik.
  • mmap_size = 268435456 (256 MB): Memetakan berkas database langsung ke ruang memori virtual sistem operasi (Memory-Mapped I/O). SQLite membaca data dashboard langsung dari memori tanpa memicu pemanggilan sistem call `read()` CPU.

B. Struktur Indexing Kueri Cepat

Indeks khusus dibangun pada fase inisialisasi database untuk meniadakan FULL TABLE SCAN:

-- Covering Index untuk Kueri Dashboard (Grafik Backbone 7 Hari)
CREATE INDEX IF NOT EXISTS idx_metrics_name_time 
ON snmp_metrics(metric_name, timestamp, device_id, metric_value);

-- Index Pencarian Metrik Per-Device
CREATE INDEX IF NOT EXISTS idx_metrics_device 
ON snmp_metrics(device_id, metric_name, timestamp);

-- Index Pemuatan Cepat Operasi Database Cleanup
CREATE INDEX IF NOT EXISTS idx_metrics_timestamp ON snmp_metrics(timestamp);
CREATE INDEX IF NOT EXISTS idx_traffic_timestamp ON interface_traffic(sampled_at);

6. Alur Kerja Logika Latar Belakang (Schedulers)

NetMon menggunakan pustaka APScheduler di dalam file app.py untuk mengoordinasikan loop pekerjaan asinkron di thread terpisah.

Pemisahan Tugas Penjadwalan (Schedulers)

  1. Status Polling Job (Setiap 30 Detik):
    • Mengambil data devices dengan status snmp_enabled = 1 dari DB.
    • Memasukkan ke dalam `ThreadPoolExecutor` asinkron untuk memanggil fungsi poll_device secara paralel.
    • Jika gagal, jalankan evaluasi PingFallback ganda. Jika terbukti down, record alert dan analisis forensik dijalankan.
  2. Traffic Polling Job (Setiap 10 Detik):
    • Mengeksekusi walk SNMP khusus untuk mengambil counter byte `ifHCInOctets` / `ifHCOutOctets` pada devices berjenis `router`.
    • Menghitung delta bandwidth lalu memasukkan data resolusi tinggi ke database.
    • Menjalankan fungsi pembersihan data lawas (Split Retention) di akhir loop kueri.
  3. Database Weekly Vacuum (Setiap Hari Minggu 03:00):
    • Menjalankan pembersihan fisik database secara berkala via perintah VACUUM untuk menyusutkan file `netmon.db` di sistem operasi.

7. Diagnostik Kegagalan Jaringan (BlackBox Forensics)

Ketika status perangkat beralih dari online (`up`) ke offline (`down`), NetMon mengaktifkan modul BlackBox Forensics yang mengevaluasi data sensor performa sebelum downtime terjadi untuk menentukan penyebab kegagalan secara heuristik.

Logika Diagnosa Heuristik

  • Thermal Shutdown: Jika suhu perangkat sesaat sebelum mati melebihi 85°C, diagnosa disimpulkan sebagai Overheating / Thermal Protection.
  • Memory Leak: Jika konsumsi RAM > 95% sedangkan utilisasi CPU normal, kegagalan diidentifikasi sebagai kebocoran memori (Memory Leak).
  • DDoS & Bandwidth Saturation: Jika total lalu lintas data `wan_in`/`wan_out` router menyentuh ≥ 95% dari nilai uplink_speed_mbps perangkat, diagnosa disimpulkan sebagai Congestion / Serangan DDoS.
  • Mass Failure (Distribution cut): Jika terdapat ≥ 2 perangkat yang mati secara bersamaan dalam jeda waktu 30 detik, sistem mengabaikan diagnosa lokal dan menetapkan diagnosis Upstream Link Failure / Mass Fiber Cut.

9. Daftar Fungsi Utama Codebase & Kerja Logika

Berikut adalah peta fungsi terpenting di dalam codebase NetMon yang mendukung operasional backend asinkron:

Fungsi pada database.py (Data Engine)

  • conn(self): Connection provider dengan mekanisme RLock multithreading untuk mencegah lock SQLite pada server Flask. Menyediakan tuning parameter PRAGMA.
  • cleanup_interface_traffic(self, interface_retention_hours, metrics_retention_hours): Logika retensi data terpisah. Menghapus grafik resolusi tinggi (`interface_traffic`) dan performa bulanan (`snmp_metrics`) secara berkala.
  • generate_and_save_monthly_report(self, month_str): Mengisolasi data bulan kalender terkait, menghitung throughput rata-rata terbobot waktu (Time-Weighted Average), dan memfilter traffic anomali secara AI.

Fungsi pada snmp_worker.py (SNMP Worker)

  • poll_device(self, device): Logic pemeriksaan online perangkat. SNMP Timeout → PingFallback (ICMP + TCP Connect) → Simpan Status → Broadcast status via Socket.IO.
  • collect_interface_traffic(self, device): Melakukan SNMP walk 64-bit/32-bit counter bytes. Mengkalkulasi bps = (delta_bytes * 8) / dt. Menerapkan rollover protection dan discard anomali di atas physical capacity.
  • analyze_downtime_event(self, device, ...): Implementasi heuristik BlackBox Forensics untuk mengevaluasi data metrik sebelum status kegagalan terekam.

10. Prosedur Pemeliharaan & Troubleshooting

Panduan praktis untuk menangani kendala teknis operasional pada deployment NetMon.

A. Troubleshooting Umum

1. Status Perangkat Terbaca "Unknown" atau Selalu "Down"

Penyebab: Target host tidak merespons SNMP/Ping akibat firewall port atau community string salah.
Solusi: Lakukan uji coba konektivitas manual menggunakan utilitas CLI server. Contoh: ping <IP-Device> dan snmpwalk -v 2c -c public <IP-Device> 1.3.6.1.2.1.1.1.0. Pastikan port UDP 161 terbuka di sisi client/router target.

2. Penggunaan CPU Server Sangat Tinggi

Penyebab: Interval polling SNMP disetel terlalu rapat sedangkan jumlah perangkat yang dimonitor berjumlah besar (> 100 perangkat).
Solusi: Masuk ke halaman Settings di dashboard Web, naikkan parameter Poll Interval menjadi 60 detik atau lebih untuk mereduksi beban workload thread pool backend.

3. File Database netmon.db Membengkak

Penyebab: Retensi metrik disetel terlalu panjang atau database SQLite belum membebaskan block disk kosong yang telah dihapus.
Solusi: Pastikan job scheduler run_weekly_vacuum berjalan normal setiap hari Minggu, atau lakukan vacuum manual melalui antarmuka CLI sqlite: sqlite3 netmon.db "VACUUM;".

B. Catatan Keamanan Produksi

  • Reverse Proxy: Aplikasi Flask NetMon tidak dilengkapi authenticator login bawaan. Wajib dipasang di belakang Reverse Proxy (e.g. Nginx/Caddy) dengan pengaktifan modul HTTP Basic Authentication untuk mencegah bypass akses eksternal.
  • Access Control List (ACL): sandi SNMP community string ditransmisikan dalam bentuk plain-text di jaringan. Batasi kueri OID SNMP di sisi router/switch hanya untuk IP server monitoring NetMon.
